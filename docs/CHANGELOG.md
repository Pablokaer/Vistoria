# Changelog

Every code change is recorded here (newest first), together with the docs it touched.

## 2026-10-17

- **Product name: Olhai.** See [ADR 0020](architecture/0020-product-name-olhai.md).
  - **Web:** a single `PRODUCT_NAME` constant (`frontend/src/lib/brand.ts`) feeds the logo (`Brand`: sidebar, phone drawer, sign-in and register pages, public header and footer), the page title template (`… · Olhai`), the share preview name and the copyright lines. The interface texts that named the product (auth, billing, landing metadata) say Olhai in English and Portuguese.
  - **PDF report:** the logo, the footer of every page and the document metadata (`Creator`) use `PdfTheme.ProductName`.
  - **Unchanged on purpose:** the internal code name InspectFlow (C# namespaces, database `inspectflow`, Docker images and containers, the AI writing guide).
  - **Tests:** new `Report_carries_the_product_name_olhai_not_the_internal_code_name`, 209 backend tests in total. `e2e/landing.mjs` checks the logo and the page title.
  - **Launcher:** `run-project.sh` prints "Olhai is running".
  - **Docs:** README, ADR 0020, implementation report.
- **Landing page image performance.** Measured on a cold cache, after scrolling the whole page: images went from 295 KB to 138 KB on mobile (390px, DPR 3) and from 256 KB to 100 KB on desktop (1440px). LCP and CLS are unchanged, with CLS 0 on both.
  - `next.config.ts` serves AVIF first, with WebP as the fallback. It also declares the `qualities` allowlist `[50, 75]`, which Next 16 requires before any quality other than the default can be used.
  - The AI section's blurred backdrop now uses the same `sizes` as the phone photo (`PHONE_PHOTO_SIZES`), so the bedroom photo is downloaded once instead of twice.
  - The closing call to action's dusk photo, the page's heaviest, is served at quality 50. It sits under an 80–95% veil, so the difference does not show.
  - Docs: ADR 0019, implementation report.
- **Landing page review fixes.**
  - Escape now closes the mobile menu and moves focus back to the menu button. Before, focus was left on `<body>`.
  - The mobile menu's height cap matches the 4.5rem header, so the menu no longer runs past the viewport.
  - The language switcher in the mobile menu keeps its own width (`justify-self-start`).
  - The hero headline's text keeps spaces between its lines, which matters for search snippets and copy-paste. Below 360px the pt-BR "sem complicação." line steps down to 2rem so it is not clipped.
  - Blocks that were never revealed print visibly.
  - `useScrollFlag` writes the DOM only when the flag changes.
  - The "For agents" photo card gets its strings from its parent instead of resolving the translator again.
- **Landing page redesign.** See [ADR 0019](architecture/0019-landing-page-redesign.md).
  - **Design:**
    - White and cool-grey surfaces with one brand blue (`#1769E0`), defined as new `site-*` tokens in `globals.css`.
    - Inter only; the Newsreader serif is removed.
    - Architectural photography: four Unsplash photos kept as local, optimized copies in `frontend/src/assets/landing`, with credits in `CREDITS.md`, served through `next/image` (blur placeholder, responsive sizes, hero preload).
    - Secondary text is `#5B6B80` so it passes AA on both backgrounds.
  - **Sections:**
    - Sticky header: gains a hairline and a shadow on scroll. The mobile menu closes with Escape.
    - Hero: the photo fades into the text column, with a room status card that uses the app's success badge.
    - Four feature cards: each ends with the concrete mechanism behind its claim.
    - AI section: a phone mockup of the inspector's *Descriptions* step, drawn with the app's real labels, in front of a photo of the same room.
    - "How it works": four connected stages, across on desktop and down the left edge on phones.
    - "For agents": a *Join as an agent* link to `/register?role=Agent`.
    - Pricing: still from the API.
    - Final call to action: on a dusk photo, with *Sign in* as the second action.
    - Footer: product and account links.
  - **Not included:** no Contact link, because the product has no contact address or page, and no legal links, because there are no legal pages.
  - **Removed:** the report specimen, workflow ledger, report guarantees, dispatch routes, room sketches and the serif font.
  - **Motion:** `Reveal` raises below-the-fold blocks once, after hydration. It is skipped with `prefers-reduced-motion`.
  - **Tests:**
    - `e2e/landing.mjs` now checks every call to action, layouts at 375/430/768/1024/1440/1920 px, and axe WCAG 2.2 AA on the fully revealed page.
    - `e2e/subscription.mjs` checks that Escape closes the mobile menu.
    - The hero expectations in `localization.mjs` and `subscription.mjs` are updated.
  - **Docs:** README, ADR 0019 (ADR 0018 marked as superseded for its visual part), implementation report.

## 2026-10-16

- **New public landing page and session-aware "/".** See [ADR 0018](architecture/0018-landing-page-and-root-routing.md).
  - **Design:** a "paper record" visual language for public pages (paper surface, ink rules, navy actions, Newsreader serif headlines through `next/font`, Move In teal and Move Out orange as the only accents).
  - **Sections:** hero with a specimen of a finalized Move Out report, a four-step workflow ledger, report guarantees with a Move In / Move Out comparison, the three dispatch routes (team, marketplace, private invitation), pricing from the API, a final call to action and a footer.
  - **Removed:** the old landing sections (audience, 7-step, highlights, 12-feature grid, product mockup) and their message catalog. `/pricing` uses the new sections.
  - **Routing:**
    - The API now also sets the `if_session` hint cookie (HttpOnly, `Path=/`, Lax, no secret) whenever it issues tokens, and removes it on logout and on a failed refresh. It is kept when the failure is only a parallel tab's rotation (new 401 code `auth.refresh_superseded`).
    - The root layout reads the hint. Anonymous visitors get the landing page rendered on the server with no refresh call, so the 401 console error is gone.
    - Signed-in visitors of "/" go to their home without the landing page being rendered. A stale hint falls back to the landing page.
  - **Tests:**
    - `SessionHintCookieTests` (4) cover the hint set on sign-in, renewed on refresh, removed on logout and on a failed refresh, and kept on a parallel tab's rotation. The existing web-cookie test now selects `if_refresh`.
    - `e2e/landing.mjs` covers anonymous server rendering, entry points, protected route, viewports (375/768/1024/1440), axe WCAG 2.2 AA, the signed-in redirect, reload, logout and session expiry.
    - The e2e hero expectations are updated. `axe-core` 4.13.0 is a new e2e dependency.
  - **Docs:** README, ADR 0018, implementation report.
- **Sidebar language switch.** The small EN/PT dropdown in the sidebar footer is replaced by a visible two-position **PT | EN** switch (`components/shell/LanguageToggle.tsx`) next to the "Language" label. It is also in the phone drawer. It uses the same `locale` cookie as before, so the choice still applies to the whole app and survives reloads. Public pages keep the compact selector. The UI flow (`e2e/team.mjs`) switches a signed-in agent to Portuguese and back through it. Docs: README.

- **Company team agents and Team inspections.** See [ADR 0017](architecture/0017-company-team-agents.md).
  - **Team:**
    - A company registers its own agents on the new *Agents* page (`/company/agents`). A new email creates the agent account with an initial password; an email that already has an agent account is linked as is.
    - API: `GET`, `POST /api/companies/me/agents` and `DELETE /api/companies/me/agents/{agentId}`.
    - Only Owner/Admin can register or remove agents; any company member can list them.
  - **New visibility `Team`:**
    - Listed in *Available* only to the company's team agents; other agents get 404.
    - Option 1: open to the whole team, and the first agent to accept takes it.
    - Option 2: assigned directly to one agent (`assignedAgentId` on create), so the inspection is Assigned on publish with no accept step.
  - **Assignment panel:** on the inspection page the company can assign, switch the agent or *release to the team* until the agent starts. API: `PUT /api/inspections/{id}/assignment`. The state machine gains Assigned → Open.
  - **Notifications:** the agent is notified when added to a team, every team agent when a Team inspection is published, and the chosen agent when one is assigned to them.
  - **Backend:**
    - New `CompanyAgent` entity and migration `AddCompanyAgents` (`companies.company_agents`).
    - `CompanyAgentService` and `TeamAssignmentService`.
    - `UserAccountFactory` is now shared by self-registration and team registration (extracted from `AuthService`).
    - Agent visibility rules are centralised in `InspectionAccess` (`OpenForAgent`, `CanAgentSeeAsync`).
  - **Seed:** `agent@demo.local` is registered in the demo company's team, including on databases seeded earlier.
  - **Tests:**
    - `TeamAssignmentDomainTests` (6) cover designation, reassignment, release and the visibility guard.
    - `TeamAgentTests` (8, HTTP + PostgreSQL) cover account creation and linking, duplicates, visibility to outsiders, assignment at creation, hidden designated drafts, reassignment and release, and removal.
    - Two new state-machine cases.
    - The UI flow gains a team scenario (`e2e/team.mjs`).
  - **Docs:** README, ADR 0017, implementation report.

## 2026-09-30

- **PDF report redesign.** See [ADR 0016](architecture/0016-pdf-report-layout.md).
  - **Structure:**
    - `PdfTheme` holds the tokens and `PdfIcons` the line icons and logo.

    - `QuestPdfReportService` only assembles the document.
  - **Page breaks:**
    - A room header stays with its photos.
    - Condition text stays with the last photo row.
    - A single photo sits beside a short condition.
    - A defect description sits beside its photos.
    - "Possible changes" and the inspector's decision form one block, so the decision is never orphaned on the next page.
    - The summary, including report details, stays on one page.
  - **Fix:** Move Out reports now load the Move In photos (`ReportImageLoader.PhotoKeys` includes `Comparison.BaselinePhotos`). Before, the Before column showed "Photo unavailable".
  - **Removed:** the unused `ReportPdfText.Classification` label.
  - **Tests:**
    - `ReportPdfRenderingTests` renders seven scenarios from `Support/ReportSamples`: no defects, defects, many photos, long texts, optional data missing, Move Out en and pt-BR.

    - With `PDF_PREVIEW_DIR` set, the tests write each PDF and its page PNGs for review.
- **Product UI redesign (frontend only; no endpoint, rule or state changed).** See [ADR 0015](architecture/0015-design-system.md).
  - **Design system:** tokens in `app/globals.css` (type scale, neutrals, brand blue, semantic tones, Move In / Move Out / Periodic identities, radii, shadows, widths, motion), the Inter font through `next/font`, and inline icons (`components/icons.tsx`). The primitives in `components/ui/*` replace `components/ui.tsx`: StatusBadge with icon and label, MetricCard, EmptyState, Skeleton, Tabs, ProgressRing, Switch, toasts, and `useConfirm` instead of `window.confirm`.
  - **Shell:** a navy sidebar per role with notifications (titles translated from the notification type), profile, language and sign-out. On phones, a top bar, a drawer and bottom tabs; the tabs are hidden during inspection execution. The dev account switcher is now a discreet chip.
  - **Inspector:**
    - The dashboard shows the current inspection with a Continue button, compact metrics, a marketplace preview and recently completed inspections.
    - The marketplace gets search, filters and sorting (client-side).
    - *My inspections* is a single tabbed view.
    - A new inspection details page with a next-step panel.
    - Execution:
      - A step header on every page.
      - Room navigation: side list on desktop, chip strip on phones.
      - A capture area with a large *Take photo*, a viewer and retry.
      - AI draft states with "Restore".
      - Defects that expand when needed.
      - A Before/After comparison.
      - Sticky action bars.
  - **Company:** a pipeline dashboard, a property table, a sectioned property page and forms, and an inspection timeline built from the real timestamps.
  - **Tenant:** a simple dashboard (awaiting review first) and a response panel.
  - **Reports:** a document layout with a photo lightbox and a side panel (contents, review, versions, integrity), plus *Share report* for companies.
  - **Sign-in, sign-up and checkout:** aligned with the new look.

  - **Tests:** the e2e now clicks the in-app confirmations (*Yes, finalize*, *Yes, the report is correct*). `tsc`, `eslint`, the Docker production build and the full UI flow pass.

- **English and Brazilian Portuguese across the platform.** See [ADR 0014](architecture/0014-localization.md).
  - **Web:** every page and component has both languages, with catalogs in `frontend/src/i18n/messages/*.ts` built on a small dependency-free i18n core (`src/i18n`). The first language comes from the browser; the **EN / PT** switcher in the app header, the landing header, sign-in/register and checkout changes it and stores the choice in the `locale` cookie. Server components render in the right language on the first byte. Dates, money and enum labels are localized, and `lib/format.ts` was removed.
  - **Company Settings page** (`/company/settings`) with the **report language**. Onboarding sends the owner's current language as the company's report language.
  - **API:** every user-facing message (about 170: validation, domain rules, room completion issues, not-found, 402, 429, Identity and AI errors) is a `LocalizedText`, and the string-only exception constructors were removed. The language comes from `Accept-Language` through `UseRequestLanguage` (`AsyncLocal`, because globalization is invariant). Codes are unchanged, and English is still the default.
  - **Plans:** optional `Translations.pt-BR` in `Billing:Plans`.
  - **Reports:** the snapshot records `language` (schema v2; v1 reads as English), and the PDF's labels and dates follow it (`ReportPdfText`).
  - **Tests:** 37 new backend tests (178 in total). The e2e flow adds `e2e/localization.mjs`: a Portuguese browser, the switcher and cookie, and a Portuguese API error.

- **Company report language (`en` / `pt-BR`).** `Company.ReportLanguage` (migration `AddCompanyReportLanguage`, default `en`) sets the language of the company's reports and AI drafts. `POST /api/companies` accepts an optional `reportLanguage`; `PUT /api/companies/me/report-language` changes it (Owner/Admin, audited); `/api/auth/me` and `GET /api/companies/me` return it. New `Shared/Localization`: `SupportedLanguages` (tag resolution/validation) and `LocalizedText` (one text in every supported language), the base for the bilingual UI and API messages. Tests: `LocalizationTests`, `CompanyReportLanguageTests`.
- **AI writing guide and report language for AI drafts.** New team-maintained guide `backend/src/Modules/AI/Guidelines/inspection-writing-guide.md` (reading order, condition criteria, materials, room/defect/comparison structure, room checklists, style, before/after examples, revision log). It is embedded and sent with every analysis after the safety rules, so improving AI drafts is a Markdown edit plus a `guide-version` bump. AI free text is now written in the company's report language (`en` → British English, `pt-BR` → Brazilian Portuguese); JSON keys and condition/classification codes stay in English. `prompt_version` records code, guide and language (e.g. `2026-09-v2+g2026-09-30.1+pt-BR`). The mock provider names the language in its label. See [ADR 0013](architecture/0013-ai-writing-guide-and-language.md). Tests: `WritingGuideTests` (guide parsing, prompt order, language rule, OpenAI system message, prompt version).
- **`run-project.sh` is executable in git** (mode 100755), so `./run-project.sh` works straight after cloning on Linux/macOS without `chmod +x`.
- **Public landing page and mandatory subscription.** `/` is now a public landing page with a hero product mockup, the audiences, how it works, highlights, features, pricing and a final CTA; its header has a mobile menu, Sign in and Get started. New pages: `/pricing`, `/checkout` (plan + order summary), `/checkout/sandbox/[sessionId]` (development payment page), `/subscription/success` (polls until the webhook activates the subscription), `/subscription/required` (unpaid, abandoned or lapsed accounts) and `/app` (sends each user to their home). `/register?plan=…` is the company step of the flow. Backend: new `Billing` module (`Subscription`, `CheckoutSession`, `BillingEvent`; migration `AddBilling`), `IPaymentProvider` with Stripe and Sandbox implementations, signed and idempotent webhooks at `POST /api/billing/webhooks/{provider}`, and an `ActiveSubscriptionRequirement` on the role policies (402 `subscription.required`). Roles that pay are configured in `Billing:SubscriptionRequiredRoles` (default: Company). `/api/auth/me` includes a `subscription` summary. The demo company is seeded with an active subscription. The brand colour moves from teal to blue. See [ADR 0012](architecture/0012-subscription-billing.md). Tests: 30 new backend tests (116 in total), and the UI flow now covers landing → subscribe and abandoned checkout → sign in → resume → dashboard.
- **Add property + inspection in one form.** *Add property* has an **Also create an inspection for this property** checkbox. Ticking it enables the inspection form (Move In / Periodic / Other, tenancy start/end date, visibility, dates, instructions, publish now); one button creates the property, the tenancy (if a start date is given; required for Move In) and the inspection. A failed inspection step keeps the property and retries only the inspection. The shared inspection fields live in `frontend/src/components/InspectionForm.tsx`, also used by *New inspection*.
- **Dev account switcher (Development only).** Header dropdown **Dev: switch account** signs in as the seeded company, agent or tenant. Backed by `GET /api/dev/accounts` and `POST /api/dev/switch`, mapped only when `ASPNETCORE_ENVIRONMENT=Development` (404 elsewhere, covered by a test).
- **Two-step agent flow.** One photos page for every room and its defects, then one descriptions page; all AI texts are requested in a single batch when leaving the photos page. See [ADR 0011](architecture/0011-capture-then-describe.md). The per-room page was removed.
- **`run-project.sh`** launcher: `up` (default), `stop`, `reset`, `logs`.
- Initial import of the MVP.
